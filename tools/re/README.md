# PC 侧分析工具

一套只读的活体分析工具。作用是：**不改代码、不重编译，直接验证内存布局假设。**

在有这套工具之前，验证一个偏移的循环是「改代码 → 编译 → 推设备 → 跑起来 → 看日志」，
一轮好几分钟；有了之后是「跑个脚本，几秒出结果」。差了一个数量级，而且不用动目标进程。

## 前置条件

- 设备已 root（`su -c` 可用）
- Python 3，`adb` 可用
- **目标必须在前台活跃运行**（见下面「为什么要前台」）

## 配置

```bash
cp config.example.py config.py   # 然后填写里面的值
```

`config.py` 已在 `.gitignore` 里。所有目标相关的常量（包名、模块名、签名、偏移）
都只存在于这个文件，工具本身不含任何目标特定值。

**如果拿到的包里已经带了 `config.py`**：那是作者按 `2026.0917` 这版 `libclient.so`
填好的，签名和偏移可以直接用，不用再从模板复制。**只需要改一项：`ADB`**。
它默认写的是 `"adb"`，前提是 adb 在 PATH 里；不在的话，改成本机 `adb.exe` 的完整路径
（Android SDK 默认装在 `<用户目录>\AppData\Local\Android\Sdk\platform-tools\adb.exe`）。
游戏热更之后偏移可能会失效，重新定位的方法见仓库根目录的 `SKILL.md`。

## 用法

```bash
python probe.py quick      # 只验锚点和指针链，几秒
python probe.py            # 全量：再加对象表统计
python probe.py --redump   # 强制重新 dump 数据段

python diff_objects.py --filter <类名子串> --list
python diff_objects.py --filter <类名子串> --bad 0x<可疑地址> --samples 4
```

### `probe.py` 输出怎么判读

| 现象 | 结论 | 下一步 |
|---|---|---|
| 根签名命中 0 处 | 引擎大改 | 活体数值扫描重新反查，成本最高 |
| 签名命中但「可用槽位 0 个」 | 签名到根指针那一跳失效 | 放宽窗口重扫，改成自愈式 |
| 多个槽位指向同一目标 | **正常**，是同一数组的多个元素 | 任选其一 |
| 对象表里「已实例化」数量符合预期 | 结构体偏移完好 | 基本没坏 |

### `diff_objects.py` 是怎么用的

场景：界面上画出了一个本不该存在的东西，你知道它的地址。把它作为 `--bad` 传进去，
工具会把同类对象的每个 4 字节列做集合比对，列出**取值完全不重叠**的偏移。
那些就是候选判据。

选判据的原则见工具最后的提示：**优先挑语义上属于「存在性」的字段**
（比如一个实例化后才非空的指针），不要挑「刚好能分开」的状态位。
状态位会随时间变化，判据迟早失效 —— 这个坑踩过。

## 三条安全规则（`memread.py` 已内建）

### 1. 只读已常驻的页

`/proc/<pid>/pagemap` 每页 8 字节，`bit63=present`、`bit62=swapped`。
读非常驻页会让内核替目标进程把页 fault 回来，**这是目标可观测的行为**。
工具只读 `bit63=1` 的页，其余跳过并打印原因。

### 2. 为什么要前台

应用切到后台会被冻结、工作集换出到 zram。此时连每帧都要遍历的核心数据页都是
`swapped`，安全检查会把读取全部拒掉，表现为「突然什么都读不出来」——
很容易被误判成偏移失效。

反过来看才是正确姿势：**目标前台活跃时工作集本来就常驻，此时读取零缺页、零风险。**
所以流程是「让目标切到前台 → 立刻读」，而不是想办法绕过检查。

### 3. maps 必须每次重新拉

目标运行中会不断新增/释放映射（实测几十分钟内 maps 能涨一千多行）。
用旧的 maps 判断地址合法性，会把目标**后来新分配区域**里的地址误判成「未映射」。

这个坑非常隐蔽：表现是「一部分对象能读、一部分读不出来」，看起来特别像
「这些对象的偏移变了」，实际上偏移完全正确。`Mem(pid)` 默认每次重新拉取。

## 其他坑

- **Windows 上 adb 拉不动含非 ASCII 字符的本地路径**：`adb pull` 会静默失败，
  不报错但文件不存在，下游报 `FileNotFoundError`，看起来像程序 bug。
  工具的中转文件都走纯 ASCII 临时目录。
- **批量读要打包成设备端脚本**：逐个地址调 `adb shell` 每次 100~300ms，
  几百页就是几分钟。把几百条 `dd` 拼成一个脚本推上去跑一次再拉回来，是秒级。
- **页对齐读**：用 `dd bs=4096 skip=<页号>`，不要用 `bs=1 skip=<字节地址>`，
  后者会逐字节读到偏移位置，慢到不可用。
- **分配器的 `---p` 区不是陷阱**：现代 Android 的 native 堆会预留大片 PROT_NONE
  虚拟地址空间。指向那里的指针只是「这个槽位没提交」，跳过即可，不用当成检测机制研究。
